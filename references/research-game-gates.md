# Research-game gates

## Before prototype testing

- Define the target construct and distinguish it from engagement.
- Version rules, stimuli, scoring, and data schema.
- Identify motor-speed, reading-load, device, language, and prior-experience confounds.
- Define formative feedback and no-feedback assessment boundaries.
- Specify anonymous identifiers, consent, retention, and exclusion handling.

## Before formal study

- Freeze gameplay, scoring, event order, translations, media, and CSV schema.
- Use fixed or seeded events as declared in the protocol.
- Confirm equivalent assessment forms and no answer leakage.
- Run deterministic scoring fixtures and end-to-end export checks.
- Record build/config version in every session.
- Complete expert content validation and pilot testing.

## Reward-hacking protection

Do not select a design merely because it raises the formal post-test score during development. That can optimize answer exposure rather than learning. Select formative designs using comprehension, agency, usability, and validity evidence; evaluate formal learning outcomes only after the study build is frozen.

## Change control

Any post-freeze change that can affect decisions, timing, feedback, scoring, or comprehension creates a new study version and requires impact review. Cosmetic corrections may be exempt only when documented and shown not to affect behavior.
