# Visual, motion, art, and audio pipeline

## Visual approval gate

After the user selects gameplay, prepare three 16:9 gameplay mockups of the same representative scene. Keep policy/data/state/text identical. Change only visual language, composition, information hierarchy, and motion treatment.

Each mockup must show the playable surface, primary action, threat or challenge, immediate consequence, status/score feedback, and one localized language example. It must be implementable, not a promotional poster.

## Tool division

- **Website/interface skill**: responsive layout, tokens, components, keyboard/touch access, readable states.
- **Image generation**: original raster concept art, backgrounds, sprites, and style exploration. Do not trust generated text; overlay interface text in code.
- **SVG/CSS/canvas**: interactive waves, routes, meters, highlights, arrows, hit effects, and deterministic infographics.
- **Remotion**: authored news intros, consequence explanations, recaps, and exports. Do not turn the core interactive loop into passive video.
- **Browser testing**: interaction, timing, localization, responsive behavior, and runtime errors.

## Motion grammar

Every consequential animation should communicate: cause -> environmental change -> human/system effect -> trade-off. Keep decorative motion subordinate to causality. Provide reduced-motion behavior.

## Audio grammar

Specify ambience, action confirmation, warning escalation, impact, recovery, and success/failure cues. Audio must have mute and volume controls and must never be the only carrier of critical information. Use original or clearly licensed assets and preserve source/license records.

## Asset record

For each final asset store: ID, purpose, creator/tool, prompt or source, license, language dependency, dimensions/duration, version, and replacement status.
